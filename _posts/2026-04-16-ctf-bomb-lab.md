Bomb Lab은 카네기멜런대학교(CMU)가 만든 리버싱 실습이다. 6개의 phase마다 올바른 입력을 넣어야 "폭탄"이 터지지 않고 해체되는데, 그 입력을 찾으려면 바이너리를 디스어셈블해 로직을 읽어야 한다. ([CSAPP 공식 Lab 배포](https://csapp.cs.cmu.edu/3e/labs.html))

> 정답(입력값)은 적지 않는다. CMU의 교육용 과제라 정답 공개는 커닝 소스가 될 뿐이고, 어차피 직접 읽어내야 의미가 있다. 그래서 이 글은 각 phase를 어떻게 분석하는지 위주로 작성했다.

## 기본 작업 흐름

모든 phase가 같은 틀로 시작한다.

```text
gdb ./bomb
b explode_bomb        # 폭탄 함수에 먼저 브레이크 → 실수로 터져도 멈춤
disassemble phase_1   # 해당 phase 로직 확인
```

- `explode_bomb` 에 **브레이크를 걸어 두면**, 잘못된 입력을 넣어 실험해도 폭탄이 터지기 직전에 멈춰서 안전하게 관찰할 수 있다. (가장 중요한 팁)
- 입력을 매번 타이핑하기 번거로우면 파일에 적어 `r flag.txt` 로 읽힌다.
- 비교 대상이 메모리에 있으면 `x/s 주소`(문자열)·`x/d 주소`(정수)로 바로 들여다본다.

## Phase 1 — 단순 문자열 비교

가장 쉬운 단계. 디스어셈블하면 `strings_not_equal` 를 호출하기 직전에 `mov $0x40xxxx, %esi` 처럼 **비교 대상 문자열의 주소가 두 번째 인자(`esi`)에 실린다.**

```
mov    $0x4024xx, %esi      ; 비교할 문자열 주소
call   <strings_not_equal>
test   %eax, %eax
je     ...                  ; 같으면 통과
```

→ 그 주소를 `x/s` 로 읽으면 요구 문자열이 그대로 보인다. **"무엇과 비교하는지"를 메모리에서 꺼내 보는 것**, 그게 핵심이다.

## Phase 2 — 숫자 수열의 규칙 찾기

`read_six_numbers` 로 숫자 6개를 받는다. 먼저 첫 번째 값을 특정 상수와 비교하고(아니면 즉시 폭탄), 이후 루프가 돈다. 루프 본문의 패턴이 전부를 말해 준다.

```
mov    -0x4(%rbx), %eax     ; 바로 앞 숫자
add    %eax, %eax           ; ×2
cmp    %eax, (%rbx)         ; 현재 숫자와 비교
je     ...                  ; 같아야 통과
```

`-0x4(%rbx)` 는 "바로 앞 칸"(int 4바이트 간격). 즉 **각 항이 앞 항의 2배인지 검사하는 등비 수열**. 첫 항과 배수 규칙만 읽으면 입력 전체가 결정된다.

## Phase 3 — 점프 테이블(switch)

`sscanf` 로 숫자 두 개를 받는다. 반환값을 1과 비교해 최소 입력 개수를 강제하고, 첫 숫자가 범위(≤7) 안이면 점프 테이블로 분기한다.

```
cmpl   $0x7, 0x8(%rsp)      ; 첫 숫자 ≤ 7 ?
ja     <explode>            ; 초과면 폭탄
jmp    *0x402470(,%rax,8)   ; 테이블[첫 숫자] 로 간접 점프 (switch)
...
mov    $0x2c3, %eax         ; 각 case 가 서로 다른 상수를 적재
...
cmp    0xc(%rsp), %eax      ; 그 상수와 "둘째 숫자" 비교
```

C의 `switch` 가 이렇게 컴파일된다. **첫 숫자가 case를 고르고, 그 case의 상수가 곧 둘째 숫자의 정답**. case가 여럿이라 **정답 쌍도 여러 개** 존재한다. 테이블 주소 `0x402470` 를 `x/8gx` 로 떠서 각 분기를 따라가면 된다.

## Phase 4 — 재귀 함수 `func4`

`sscanf` 로 두 숫자 `(A, B)`. 조건을 어셈블리에서 뽑으면:

1. 첫 숫자 `A` 는 `0 ≤ A ≤ 14` (`cmpl $0xe` / `jbe`).
2. `func4(A, 0, 14)` 의 반환값이 **0이어야** 한다 (`test %eax,%eax` / `jne <explode>`).
3. 둘째 숫자 `B` 는 **0이어야** 한다.

관건은 `func4` 다. 안을 보면 `(0+14)/2` 식으로 중앙값을 잡고 `A` 와 비교해 좌/우로 다시 자기 자신을 호출하는 — 즉 **이분 탐색(재귀)** 구조다.

```
; func4(lo, hi, A) 요지
shr    $0x1f, %ecx          ; 음수 보정 (반올림용)
...                         ; mid = lo + (hi-lo)/2
cmp    %edi, %ecx           ; mid 와 A 비교
jle    ...                  ; 분기마다 func4 재귀 호출
call   <func4>
```

반환이 0이 되려면 재귀가 특정 경로로만 흘러야 하므로, **`A` 의 후보는 범위 안에서 몇 개로 좁혀진다.** 재귀를 손으로 펼쳐 보거나, `func4` 에 브레이크를 걸고 인자를 관찰하면 보인다.

## 정리 — 어셈블리를 'C로 되읽기'

Phase 1~4를 지나며 몸에 익은 건 결국 하나였다. **낯선 어셈블리를 보면, 그게 원래 어떤 C 구조(문자열 비교 / 반복 / `switch` / 재귀)였는지로 되돌려 읽는 감각.**

- `cmp` + `je/jne` → 조건문
- `-0x4(%rbx)` 같은 접근 → 배열·인덱스
- `jmp *table(,%rax,8)` → `switch`
- 자기 자신을 `call` → 재귀

그리고 `explode_bomb` 브레이크처럼 **"안전하게 실험할 환경을 먼저 만드는"** 습관 — 이건 이후 pwn 디버깅에도 그대로 이어졌다.
