익스플로잇 기법을 아무리 외워도, 결국 "스택이 어떻게 쌓이고 RET이 어디 있는지"가 안 보이면 다 겉돈다. 그래서 공부하며 정리한 바닥 개념 — 레지스터, 메모리 구조, 어셈블리, 함수 호출 규약 — 을 내 식대로 압축했다. (작성자 본인의 학습과 같이 업데이트될 예정.)

## 1. 컴퓨터 구조와 레지스터

- **ISA(Instruction Set Architecture)**: CPU가 쓰는 명령어 설계. x86-64가 가장 널리 쓰이는 ISA 중 하나.
- 레지스터는 역할별로 나뉜다.

| 분류 | 용도 | x86-64 |
|------|------|--------|
| **범용 레지스터** | 연산·주소·인자 등 자유롭게 | rax, rbx, rcx, rdx, rsi, rdi, rsp, rbp, r8~r15 |
| **세그먼트 레지스터** | 과거 세그멘테이션, 현재는 주로 메모리 보호 | cs, ss, ds, es, fs, gs |
| **플래그 레지스터** | CPU 상태(ZF, SF, OF 등) 저장 | rflags |
| **명령어 포인터(IP)** | 다음에 실행할 코드 주소 | rip |

`rsp`(스택 포인터)와 `rbp`(베이스 포인터), 그리고 `rip`는 익스플로잇에서 특히 자주 다룬다. 공격은 결국 **`rip`가 가리키는 곳을 원하는 주소로 바꾸는 것**, 그게 목표다.

## 2. 메모리 구조 — 5개 세그먼트

프로세스 메모리는 용도별로 구획(세그먼트)되고, 각 영역에 읽기/쓰기/실행 권한이 따로 걸린다.

```
높은 주소  ┌─────────────┐
          │    Stack    │  ↓ 아래로 자람   지역변수·함수 인자·RET   (rw-)
          │      ⋮      │
          │      ⋮      │
          │    Heap     │  ↑ 위로 자람     malloc/calloc 동적할당   (rw-)
          ├─────────────┤
          │    BSS      │  초기화 안 된 전역 변수                  (rw-)
          │    Data     │  초기화된 전역/상수(.rodata 포함)        (rw- / r--)
          │    Code     │  실행 코드 (main 등)                     (r-x)
낮은 주소  └─────────────┘
```

- **Code(Text)**: 실행 코드. 읽기·실행만(쓰기 금지).
- **Data / .rodata**: 초기화된 전역·상수.
- **BSS**: 초기화 안 된 전역. (`.bss`에 있으면 미초기화 전역, `.data`면 초기화된 전역)
- **Heap**: 실행 중 동적 할당. 위로 자란다.
- **Stack**: 지역변수·인자·반환 주소. **아래(낮은 주소)로 자란다.**

Heap과 Stack이 서로를 향해 자란다는 점, 그리고 Code가 실행 가능(r-x)이라 NX가 없던 시절엔 스택도 실행 가능했다는 점이 익스플로잇과 직결된다.

## 3. 어셈블리 핵심

### Intel vs AT&T 문법

리눅스 디스어셈블러·pwndbg는 보통 Intel 문법으로 본다. 둘의 차이만 알면 된다.

| | 피연산자 순서 | 레지스터 | 즉시값 | 크기 |
|---|---|---|---|---|
| **Intel** | `목적지, 소스` | `eax` | `0x10` | 명령어로 유추/명시 (`DWORD PTR`) |
| **AT&T** | `소스, 목적지` | `%eax` | `$0x10` | 접미사 `movb/w/l/q` |

같은 동작 `값 5를 eax에`:

```asm
mov eax, 5      ; Intel
movl $5, %eax   ; AT&T
```

### 자주 보는 명령어

- **`mov dst, src`** — 복사/이동. 메모리 접근은 `mov rax, [rdi]`(rdi가 가리키는 값을 rax로), 크기는 `BYTE/DWORD/QWORD PTR`로 지정.
- **산술** `add / sub / mul·imul / div·idiv` — `add rax, rbx`는 `rax += rbx`. 곱·나눗셈은 `RDX:RAX`처럼 레지스터 쌍을 쓴다.
- **논리** `and / or / xor / not` — `xor rax, rax`는 **rax를 0으로** 만드는 관용구.
- **비교·분기** `cmp`(뺄셈으로 플래그 갱신) / `test`(AND로 플래그 갱신) 후 `je/jg/jmp…`로 분기. `test rax, rax` 뒤 `je`면 "rax가 0이면 점프".

### 변수 접근 패턴 (이게 분석에 제일 유용)

- **전역변수**: `rip` 기준 상대 주소로 접근 (PIE 대응).
- **지역변수**: `rbp - N` 으로 접근.

디스어셈블리에서 `[rbp-0x8]` 같은 게 보이면 "지역변수", `[rip+0x...]` 면 "전역변수"로 바로 읽으면 된다.

## 4. 함수 호출 규약 (SYSV)

함수를 호출하면 흐름이 호출자(Caller)→피호출자(Callee)로 넘어갔다가 **돌아와야** 한다. 그 "돌아올 수 있게 해주는 약속"이 호출 규약이다. 리눅스 x86-64는 **System V ABI**, 줄여서 SYSV ABI를 쓴다.

- **인자 전달**: 앞 6개는 순서대로 `RDI, RSI, RDX, RCX, R8, R9`. 7번째부터 스택.
- **반환 값**: `RAX`.
- **스택 정리**: 호출자(Caller)가 한다.

> 인자 레지스터 순서 `RDI·RSI·RDX·RCX·R8·R9` 는 ROP로 `system("/bin/sh")`를 호출할 때 **첫 인자를 `rdi`에 넣어야** 하는 이유 그 자체다. (그래서 `pop rdi; ret` 가젯을 찾는다.)

### 스택 프레임 — 프롤로그와 에필로그

함수가 호출될 때 스택은 이렇게 쌓인다.

```
높은 주소
  │  ... caller 프레임 ...  │
  ├────────────────────────┤
  │   Return Address        │ ← call 이 push (리턴 후 돌아갈 주소)
  ├────────────────────────┤
  │   Saved RBP             │ ← push rbp (호출자의 rbp 보관)
  ├────────────────────────┤ ← 현재 RBP
  │   지역변수 [rbp-0x8]     │
  │   지역변수 [rbp-0x10]    │
  │        ...              │
  ├────────────────────────┤ ← 현재 RSP
낮은 주소
```

- **프롤로그**: `push rbp` → `mov rbp, rsp` → `sub rsp, N` (지역변수 공간 N바이트 확보).
- **에필로그**: `leave`(= `mov rsp, rbp; pop rbp`) → `ret`(= RET 주소를 pop 해서 rip로).

## 5. 그래서 스택 버퍼 오버플로가 터진다

지역변수 버퍼는 `rbp - N` 쪽(낮은 주소)에 있고, Return Address는 그보다 **높은 주소에 있다**. 그런데 `gets`·`strcpy`처럼 길이를 검사하지 않는 입력이 버퍼 크기를 넘기면, 쌓이는 방향 때문에 **버퍼 → Saved RBP → Return Address 순으로 덮인다.**

Return Address를 내가 원하는 값으로 덮으면, 함수가 `ret` 하는 순간 그 주소로 `rip`가 점프한다 — 이게 모든 스택 기반 익스플로잇의 출발점이다.

> 여기서부터 "덮은 주소에 뭘 넣느냐(쉘코드 / libc / ROP)"와 "보호기법을 어떻게 걷어내느냐"로 갈라진다. 그 흐름은 『[Pwn 익스플로잇 기법 정리](/tech/tech-pwn-exploitation/)』에 이어진다.
