화이트햇 스쿨(WHS) 1기에서 **분석팀**(취약점을 찾는 쪽)으로 참여한 프로젝트다. 개발팀이 만든 실습용 쇼핑몰(**OFAD**)을 대상으로, 워게임 문제가 아니라 "실제로 돌아가는 웹서비스"를 점검해 봤다. 결론부터 말하면 블랙박스에서 확실한 취약점을 뚫어내진 못했는데, 그 과정과 못 뚫은 이유를 솔직하게 정리한다.

## 어떻게 준비했나

점검 전에 기반을 다지는 데 시간을 꽤 썼다.

- **OWASP Top 10** — 2021/2022 기준 주요 취약점 카테고리를 먼저 정리.
- **OWASP Juice-shop** — 의도적으로 취약하게 만든 공개 쇼핑몰로 사전 실습. Login(Admin/Bender/Jim), DOM XSS, Admin Section, View Basket 등을 실습하며 "쇼핑몰에서 어디를 보는지" 감을 잡음.
- **DreamHack 워게임** — XSS, CSRF, SQLi, command injection, SSRF, 파일 다운로드, 세션 등 웹 취약점 유형을 폭넓게 연습하며 기법을 손에 익힘.
- **Arachni 스캐너 환경 구축** — Windows VM(Ubuntu)에 Arachni를 올려 자동 스캔 환경을 세팅.

```bash
# Arachni 1.6.1.3 설치 (Ubuntu VM)
wget https://github.com/Arachni/arachni/releases/download/v1.6.1.3/arachni-...-linux-x86_64.tar.gz
tar -xvf arachni-*.tar.gz
cd arachni-*/bin && ./arachni_web        # https://localhost:9292 접속
```

점검은 **블랙박스 / 화이트박스 / 스캐너** 세 방향으로 나눠 진행했고, 발견한 내용은 취약점별로 보고서 형식으로 정리했다.

## 블랙박스 점검 — 실제로 해본 것

### XSS — 게시판과 닉네임

문의·후기 게시판과 닉네임 입력란이 사용자 입력을 그대로 보여주는 지점이라, XSS가 될 것 같아 집중적으로 시도했다. 기본형부터 우회형까지 10여 종을 넣어 봤다.

```html
<script>alert('Hi')</script>
<img src="invalid" onerror="alert('Hello')">
<scr<script>ipt>alert('Hi')</scr<script>ipt>   <!-- 중첩으로 필터 우회 시도 -->
<ScrIpT>AlerT('1')</scRIPT>                     <!-- 대소문자 변조 -->
%3CScRipT%3EALert('1')%3cScriPT%3E              <!-- URL 인코딩 -->
"xss" + onkeydown="alert(1)"                     <!-- 이벤트 핸들러 -->
<iframe src="javascript:alert(1)">
```

결과는 **전부 실패**. 태그 제거·인코딩 처리 등 입력 필터링이 걸려 있어서, 내가 시도한 구문으로는 스크립트가 실행되지 않았다. (JSFuck 같은 난독화 페이로드까지 넣어 봤지만 마찬가지)

### SQL Injection — 로그인

로그인 폼에 `'` 를 넣어도 Syntax Error가 나지 않았다. 에러 기반으로 접근할 단서가 안 보여서, 이 지점에서 SQLi로 파고들기는 어렵다고 판단했다.

### 비밀번호 변경 동작

비밀번호 변경 기능에서, 변경 자체는 성공하는데 완료 후 404가 뜨는 동작을 관찰했다. 비밀번호 정책(조건)을 안 맞추면 변경이 막히는 것도 확인했다. 흥미로운 동작이었지만, 권한 상승 같은 실제 악용으로 잇진 못했다.

### Insecure Deserialization

역직렬화 취약점은 개념을 학습하고 적용 가능성을 살펴보는 선에서 그쳤다.

## 솔직한 결과와 원인

블랙박스에서 **확실하게 "뚫었다"고 할 만한 취약점은 찾지 못했다.** 이유를 돌아보면:

- **개발팀이 보안 패치·라이브러리 최신화를 꽤 꼼꼼히 해뒀다는 점**, 이게 컸다. 코드를 들여다보면 알려진 취약점이 대부분 막혀 있었고, 입력 필터링(태그 제거·인코딩)도 기본적으로 갖춰져 있어 교과서적인 페이로드는 거의 다 걸렸다.
- 필터가 있을 때 그걸 **어떻게 우회할지** 체계적으로 좁혀 가는 수동 검증 숙련도가 아직 부족했다. 변형을 "많이" 넣어 봤지만, 필터 로직을 역으로 분석해 표적화하진 못했다.
- 스캐너(Arachni) 결과도 결국 수동으로 검증해야 의미가 있는데, 그 검증을 끝까지 끌고 가는 힘이 모자랐다.

## 배운 점

- **실제 서비스는 워게임과 다르다.** 워게임은 "여기에 취약점이 있다"가 전제지만, 실서비스는 취약점이 있는지부터 내가 증명해야 한다. 이 감각을 처음 체감했다.
- 자동 스캐너는 출발점일 뿐이고, **본체는 수동 검증**, 그걸 배웠다.
- 그리고 가장 중요한 수확 — "공부한 기법"과 "실제로 뚫은 결과" 사이엔 **생각보다 큰 간극이 있었다**. 그걸 몸으로 알았다. 이 간극은 이후 우리콘(버그바운티)에서 다시, 더 뼈아프게 마주하게 된다.

> 이 경험은 지금도 내 약점이자 다음 과제다. 기법을 아는 것과 실제 대상에서 취약점을 발굴하는 것은 다른 능력이고, 나는 아직 후자가 부족하다 — 그걸 인정하는 데서 다음 공부가 시작된다고 생각한다.
